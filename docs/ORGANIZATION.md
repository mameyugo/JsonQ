# Binary Organization Strategy

To maintain a clean and structured repository for multiple versions of the JsonQ extension, binaries are organized by operating system and PHP version.

## Directory Structure

Binaries should be placed in the `bin/` directory following this pattern:

```text
bin/
├── linux/
│   ├── php8.1/
│   ├── php8.2/
│   ├── php8.3/
│   │   └── jsonq.so
│   └── php8.4/
├── windows/
│   ├── php8.1/
│   ├── php8.2/
│   ├── php8.3/
│   └── php8.4/
└── macos/
    ├── php8.1/
    ├── php8.2/
    ├── php8.3/
    └── php8.4/
```

## File Naming Conventions

| OS | Extension | Filename |
| :--- | :--- | :--- |
| **Linux** | `.so` | `jsonq.so` |
| **Windows** | `.dll` | `jsonq.dll` |
| **macOS** | `.dylib` | `jsonq.dylib` (or `jsonq.so`) |

## How to update binaries

1.  **Locally**: After a successful build, copy the library from `target/release/` to the corresponding `bin/` folder.
2.  **GitHub Actions**: Binaries generated by GitHub Actions can be downloaded as artifacts. You should manually download them and place them in this structure before a release if you want to track them in the repository.

> [!NOTE]
> The `/target` directory is ignored by Git, but the `/bin` directory is tracked to allow distribution of pre-compiled binaries.
